# Insight (DR26-08-05-HUB-02-2156): можно ли читать свои посты личного профиля Facebook без браузера

> **Потребитель:** конвейер `fb-watch` (пост на стене FB → тизер в @ClawRus). Сейчас жатва держится на залогиненном браузере — единственное хрупкое звено. Вопрос был: есть ли легальная замена.
>
> **База синтеза:** 4 рельсы из 6 (кворум). ChatGPT (Pro + Web search, 53 мин, 43 источника Meta) · GLM-5.2 (Advanced Search, 23 источника с датами) · Gemini (Pro Extended, Deep research, 12 разделов) · Grok (Heavy, 518 sources). claude.ai не успел в окно сессии (Research шёл 58+ мин). Mistral — рельса недоступна, аккаунта нет.

## Ответ на главный вопрос: ДА, официальный путь есть

Не «возможно» и не обтекаемо. Четыре рельсы из четырёх сошлись:

**`user_posts` жив.** Разрешение существует в актуальной версии Graph API **v26.0, выпущенной 29.07.2026**. Эндпоинт `GET /me/posts` документирован для личного профиля владельца токена и отдаёт ровно то, что нужно конвейеру: `id` (стабильный), `message` (полный текст), `created_time`, `permalink_url`.

Распространённое «Facebook закрыл чтение личных профилей» — **неверно применительно к владельцу токена**. Верно оно для чтения чужих профилей. ChatGPT отдельно разобрал корень путаницы: в 2018 закрыли `publish_actions` (программную публикацию в личный профиль), и это ошибочно переносят на `user_posts`.

**⭐ App Review НЕ нужен.** Это ключевой практический факт всего исследования. Если владелец аккаунта = Administrator своего же приложения, а приложение остаётся в **Development Mode**, то Standard Access выдаётся автоматически, и никакого ревью, скринкастов и Business Verification не требуется. GLM подтвердил тремя независимыми страницами Meta (Access Levels, App Roles обновлена 08.09.2025, блог про Live Mode), ChatGPT — теми же плюс Graph API Explorer Guide.

**Побочный выигрыш:** `permalink_url` отдаётся полем напрямую. Декодирование base64-параметра `content_id` и сборка `S:_I<user_id>:<story_fbid>`, на которых сейчас держится жатва, становятся не нужны.

## Где рельсы СОШЛИСЬ (перепроверять не нужно)

| Факт | Кто подтвердил |
|---|---|
| `user_posts` жив в v26.0 (релиз 29.07.2026) | все 4 |
| `GET /me/posts` отдаёт id · message · created_time · permalink_url | все 4 |
| App Review не требуется для role-holder своего app в Dev Mode | все 4, двое с цитатами из доков |
| Long-lived User Token живёт ~60 дней | все 4 |
| Content Library API для этой задачи закрыт (нужна академическая аффилиация) | все 4 |
| DYI не годится как ежедневная рельса (задержки часы–сутки, нестабильная схема, нет API запуска) | все 4 |
| Браузерная автоматизация залогиненной сессии нарушает ToS **даже для своих данных** | все 4 |
| У Threads есть `th_refresh_token` — неинтерактивное продление, которого у Facebook нет | GLM, ChatGPT, Grok |

Правовая часть сошлась жёстко и её стоит принять как факт: **Automated Data Collection Terms (в силе с 07.10.2024)** запрещают автоматизированный сбор без письменного разрешения Meta, а Facebook Terms (в силе с 01.01.2025) прямо уточняют, что запрет действует **независимо от того, залогинен ты или нет**. То, что аккаунт свой, из-под этих Terms не выводит: они регулируют способ сбора, а не владение данными. Текущий путь через Professional Dashboard формально нарушение; Graph API — предусмотренный платформой способ.

## Где рельсы РАЗОШЛИСЬ (сюда смотреть руками)

### 1. Продлевается ли токен без человека — САМОЕ ВАЖНОЕ расхождение

- **Grok:** «многие отчёты 2025–2026 подтверждают, что повторный exchange даёт новый ~60-дневный».
- **Gemini:** «официальная спецификация даёт однозначно отрицательный ответ» `[established]`.
- **GLM:** нет серверсайд-продления `[established]`; эндпоинт `fb_exchange_token` **принимает только short-lived токен**, задокументированного long→long не существует. Мнение сообществ помечено как `[emerging]` / low-authority.
- **ChatGPT:** не документирован `[established]`, но добавляет нюанс, которого нет у других: Meta пишет, что токены «refreshed once per day, when the person using your app makes a request», и **нигде не сказано, считается ли ночной серверный cron этим „person using the app“** → `[speculative]`, решается только замером.

**Разрешение:** версия Grok — слабейшая, она построена на форумных тредах, которые две другие рельсы явно пометили как низкоавторитетные. Планировать надо от «ручной re-login раз в ≤60 дней», а рост `expires_at` проверить экспериментом через `/debug_token`.

### 2. Подходит ли наш сценарий под Allowed Usage — расхождение в трактовке

Это нашёл остро только **ChatGPT**, и это единственный реальный риск замысла.

Текущий Allowed Usage для `user_posts` сформулирован узко: создание физических/цифровых **книг или альбомов** таймлайна и перенос **«memories»**. Ежедневное чтение свежих постов ради Telegram-анонсов туда прямо **не вписано**. ChatGPT: «Я не нашёл отдельного исключения для role-only Development Mode» → `[emerging]` policy ambiguity.

**GLM трактует иначе:** Allowed Usage — это критерий, по которому проходят App Review для Advanced Access, а для self-use он не применяется.

Эти две трактовки несовместимы, и ни одна не доказана. Эксперимент здесь не поможет — вопрос юридический, а не технический; снял бы его только письменный ответ Meta. Практически: риск не блокирующий (Meta не ревьюит role-only приложения), но записать его честно надо.

### 3. Отдаёт ли `/me/posts` посты, созданные ВРУЧНУЮ

GLM пометил как `[критично] к проверке`: в документации Post node соседствуют две формулировки — «a user access token can read any post **your application created** on behalf of that user» и «a user's post can be read if the owner has granted the `user_posts` permission». Вторая покрывает созданные вручную, но однозначности нет.

ChatGPT добавляет смежное: `/me/posts` может включать посты, где пользователь **отмечен**, а не автор → нужен фильтр `from.id == me.id`, иначе в Telegram уедет чужой контент.

**Это главный технический риск, и он снимается пятиминутным экспериментом.**

### 4. Page Access Token как бессрочный обход

Gemini единственный поднял: Page Access Token не истекает, и предложил «обходной путь через Page API». GLM прямо возражает: system user / page токены применимы к бизнес-активам, но **не представляют личный профиль** и не дают `user_posts`. Для нашей задачи путь не годится — но объясняет, откуда в интернете статьи «вечный токен Facebook».

### 5. Webhooks `user.feed`

Grok — «да, как дополнение». GLM — payload содержит только `{field: "feed"}` без ID и текста, нужен follow-up запрос. ChatGPT — `[emerging]`, актуального end-to-end примера 2025–2026 для личного профиля не нашёл, «не считать доказанным». Вывод: не primary, максимум триггер вместо polling.

## Что это значит для fb-watch

Браузер **убирается из критического пути** ежедневной жатвы — при одной оговорке: раз в ≤60 дней остаётся один человеческий клик по OAuth-диалогу (без ввода пароля, если сессия Facebook жива). Полностью безлюдной рельса не станет, и это надо принять честно, а не выдавать за «полную автоматизацию».

Порядок внедрения, на котором сошлись все четыре:

1. Consumer-приложение на developers.facebook.com, оставить **в Development Mode**.
2. Себя — Administrator (создатель им уже является).
3. Добавить Facebook Login, разрешение `user_posts` → **Standard Access** (не Advanced).
4. Токен через Graph API Explorer для smoke-теста, потом обмен на long-lived: `grant_type=fb_exchange_token`.
5. Боевой запрос: `GET /v26.0/me/posts?fields=id,message,created_time,permalink_url,from{id}&since=...&limit=100`, идти по `paging.next`, фильтровать `from.id == me.id`, дедуп по `id`.
6. Сторож `/debug_token`: алярм за 14/7/3 дня до `expires_at`.

Токен — в `secrets\` по правилу credential-store, **не** в волт, не в шину, не на пять узлов: держит один узел-поллер.

## Эксперименты, которые надо провести (по убыванию критичности)

1. **Отдаёт ли `/me/posts` посты, написанные вручную** — опубликовать тестовый пост, через 5 минут запросить. Если нет — весь путь рушится, и это надо знать до стройки.
2. **Есть ли `permalink_url` у постов личного профиля** (не только Page) — явный запрос поля.
3. **Растёт ли `expires_at` от ежедневного серверного polling** — снять `/debug_token` сейчас, через 24/48/72 часа и через неделю. Это и есть тот замер, который разрешит расхождение №1.
4. Доходят ли webhooks `user.feed` для личного профиля в Dev Mode.

## Оценка рельс этого прогона

- **ChatGPT (Pro + Web search)** — лучший: 53 минуты, 43 официальных источника с датами проверки, готовый Python-поллер, честные пометки `[no source found]` там, где не нашёл, разбор enforcement-прецедентов (Voyager Labs, BrandTotal). Подтверждает канон §п.10: Web search сильнее DR-чипа на этом аккаунте.
- **GLM-5.2 (Advanced Search + Deep Think Max)** — второй и очень близко: 23 источника с URL и датами, точные цитаты документации, аккуратная градация `[established]`/`[emerging]`/`[single-source]`. Рельса окупает себя.
- **Gemini** — объёмный складный текст (12 разделов, 32 КБ), но цитатная база слабая: в тексте всего 1 URL, в DOM-якорях — StackOverflow 2016–2019 и SEO-блоги. Сильная сторона проявилась в юридической части (разбор Meta v. Bright Data).
- **Grok Heavy** — быстрый (1m28s) и по сути правильный, но источники агрегированы («Developers.facebook +1») без конкретных URL, и единственная фактическая ошибка веера — про продление токена — тоже его.
